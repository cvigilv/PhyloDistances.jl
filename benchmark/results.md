# PhyloDistances.jl against its R references

Generated by `julia --project=benchmark benchmark/run.jl`.

Both implementations read the same Newick files from `benchmark/trees/`, 
and neither timing includes parsing — only the distance computation.

- Julia: minimum of a `BenchmarkTools` trial, or a single `@timed` call 
  where one call already takes seconds.
- R: median of repeated calls, looped until the clock resolution stops mattering.

**Memory is measured differently on each side and the two columns are not 
comparable.** Julia reports bytes allocated by the call; R reports the peak 
its garbage collector saw, which includes everything already resident.

## Quartet distance, one pair of trees

Quartet refuses trees above 477 tips, where the number of 
four-taxon subsets outgrows the 32-bit integers it counts them in, so the 
rows past that size have no reference to compare against.

| 1500 | 210,094,780,875 | 8.37 s | — | — | 283.49 MB | — |

`QuartetDistance`'s default `:fast` algorithm counts concordant quartets 
in `O(n³)` without enumerating them (`algorithm = :naive` keeps the exact 
`O(n⁴)` enumeration as a correctness oracle). Quartet wraps tqDist, which 
counts the same quantity in `O(n log n)` without enumerating it either — 
so the remaining gap past 477 taxa is an algorithm gap, not a language one, 
and it would still widen without bound past where this benchmark stops.

## Jaccard-Robinson-Foulds, one pair of trees

`JaccardRobinsonFoulds()` at its `k = 1, allowconflict = true` default — the 
scoring [`NyeSimilarity`](@ref) also uses. Both implementations solve an 
assignment problem over the trees' splits; `agree` uses a tolerance rather 
than exact equality because the two solvers round differently internally 
(see `validation/crosscheck.jl`'s `_closeenough`), not because either is wrong.

## Info-Robinson-Foulds, one pair of trees

`InfoRobinsonFoulds()`, which weights each split by its phylogenetic 
information content rather than counting it as one. Unlike 
Jaccard-Robinson-Foulds, this does not go through an assignment solve — 
splits are matched by identity, the same relationship classic 
Robinson-Foulds computes — so `agree` uses a tolerance only because 
TreeDist floors its result near zero (`.FloorNumericalNoise`), not because 
either side rounds an optimization differently.
